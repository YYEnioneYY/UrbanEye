# Task 001 — Website UI/UX Design

> **Цель:** разработать дизайн веб-сайта для платформы с интерактивной картой IP-камер, онлайн-просмотром мест и будущими онлайн-экскурсиями.

---

## 0. Метаданные задачи

| Поле | Значение |
|---|---|
| **Статус** | Ready for Design |
| **Ответственный** | Беляков Д.Н. |
| **Тип задачи** | Product Design / Web Design |
| **Приоритет** | High |
| **Основной инструмент** | Figma |
| **Платформы** | Desktop Web, Tablet, Mobile Web |

---

## 1. Назначение продукта

Нужно спроектировать веб-сайт, где пользователь может:

- открыть главную страницу продукта;
- понять, что сервис позволяет смотреть живые места через камеры на карте;
- перейти на интерактивную карту;
- увидеть камеры на карте;
- кликнуть на камеру и посмотреть информацию о ней;
- запустить просмотр live-видео;
- кликнуть на место на карте и получить список камер, которые смотрят на выбранную область;
- в будущем использовать сервис для онлайн-экскурсий.

Продукт должен восприниматься не как “система видеонаблюдения”, а как красивый сервис для просмотра городов, достопримечательностей, маршрутов и онлайн-прогулок.

---

## 2. Общий стиль продукта

Дизайн должен быть:

- современным;
- чистым;
- технологичным;
- визуально приятным;
- удобным для просмотра карты;
- не перегруженным;
- адаптивным;
- готовым к масштабированию.

### Ассоциации продукта

Сервис должен ассоциироваться с:

- путешествиями;
- открытием новых мест;
- живым городом;
- картой;
- камерами;
- онлайн-экскурсиями;
- безопасным и удобным просмотром.

### Чего избегать

Не нужно делать дизайн в стиле:

- охранной системы;
- CCTV-панели;
- полицейского мониторинга;
- тяжелого enterprise-интерфейса;
- перегруженной GIS-системы.

---

## 3. Основные страницы

Дизайнер должен подготовить макеты следующих страниц:

1. Главная страница.
2. Страница карты.
3. Страница камеры / состояние открытой камеры.
4. Страница онлайн-экскурсий или маршрутов.
5. Страница конкретного маршрута / экскурсии.
6. Страница “О проекте”.
7. Страница ошибки 404.
8. Базовые auth-страницы, если понадобятся:
   - вход;
   - регистрация;
   - восстановление пароля.

Для MVP обязательны:

- главная страница;
- страница карты;
- карточка камеры;
- modal/overlay видеоплеера;
- состояние клика по точке на карте;
- мобильная версия карты.

## 4. Главная страница

Главная страница должна быстро объяснять пользователю суть продукта.

### 4.1 Цель главной страницы

Пользователь должен за 5–10 секунд понять:

- что это сервис живых камер на карте;
- что можно смотреть реальные места онлайн;
- что можно открыть карту и выбрать камеру;
- что сервис подходит для прогулок, экскурсий и изучения города.

---

### 4.2 Структура главной страницы

#### Header

Должен содержать:

- логотип / название проекта;
- навигацию;
- кнопку перехода на карту;
- возможно кнопку входа.

Пример пунктов меню:

```text
Главная
Карта
Экскурсии
Популярные места
О проекте
```

Основной CTA:

```text
Открыть карту
```

---

#### Hero section

Главный экран.

Должен содержать:

- сильный заголовок;
- короткое описание;
- CTA-кнопку;
- визуал карты или mockup интерфейса;
- возможно анимированную иллюстрацию с точками камер.

Пример текста:

```text
Смотрите города в реальном времени
```

Подзаголовок:

```text
Открывайте живые камеры на карте, выбирайте места и смотрите, что происходит там прямо сейчас.
```

CTA:

```text
Перейти к карте
```

Вторичная кнопка:

```text
Посмотреть экскурсии
```

---

#### Блок “Как это работает”

Нужно показать 3 простых шага:

```text
1. Откройте карту
2. Выберите место или камеру
3. Смотрите live-видео
```

Каждый шаг должен иметь иконку и короткое описание.

---

#### Блок популярных мест

Карточки популярных камер или мест.

Карточка должна содержать:

- preview-изображение;
- название места;
- город;
- статус камеры;
- категорию;
- кнопку “Смотреть”.

Примеры:

```text
Дворцовая площадь
Невский проспект
Парк у реки
Центральная площадь
```

---

#### Блок онлайн-экскурсий

Нужен задел под будущую функциональность.

Показать, что пользователь сможет:

- проходить маршруты;
- переключаться между камерами;
- смотреть город как онлайн-прогулку;
- подключаться к экскурсии с гидом.

CTA:

```text
Смотреть маршруты
```

---

#### Блок преимуществ

Примеры преимуществ:

- живые виды в реальном времени;
- интерактивная карта;
- удобный поиск камер;
- маршруты для онлайн-прогулок;
- просмотр прямо в браузере;
- без установки приложения.

---

#### Footer

Должен содержать:

- логотип;
- ссылки;
- контакты;
- социальные сети, если нужны;
- правовую информацию.

## 5. Страница карты

Страница карты — главный пользовательский экран продукта.

Она должна быть удобной, быстрой и визуально красивой.

---

## 5.1 Основные элементы страницы карты

На странице должны быть:

- карта на весь экран или почти на весь экран;
- маркеры камер;
- кластеризация маркеров;
- фильтры;
- поиск по месту;
- карточка выбранной камеры;
- список камер рядом;
- режим клика по точке на карте;
- кнопка запуска видео;
- состояния загрузки и ошибок.

---

## 5.2 Layout страницы карты

### Desktop

Рекомендуемый layout:

```text
┌──────────────────────────────────────────────┐
│ Header / Top bar                             │
├───────────────┬──────────────────────────────┤
│ Sidebar       │ Map                          │
│ filters/list  │ camera markers              │
│ selected item │ selected point               │
└───────────────┴──────────────────────────────┘
```

Sidebar может быть слева или справа.

Sidebar должен уметь:

- показывать фильтры;
- показывать список камер;
- показывать выбранную камеру;
- показывать камеры, которые смотрят на выбранную точку.

---

### Mobile

На mobile карта должна занимать основной экран.

Рекомендуемая логика:

- карта на весь экран;
- нижняя выезжающая панель bottom sheet;
- фильтры открываются отдельным overlay;
- карточка камеры открывается снизу;
- видеоплеер открывается fullscreen.

```text
┌────────────────────┐
│ Map                │
│                    │
│ camera markers     │
│                    │
├────────────────────┤
│ Bottom Sheet       │
│ selected camera    │
└────────────────────┘
```

## 5.3 Маркеры камер

Дизайнер должен подготовить несколько состояний маркеров.

### Состояния маркеров

| Состояние | Описание |
|---|---|
| `online` | камера доступна |
| `offline` | камера недоступна |
| `maintenance` | камера в обслуживании |
| `unknown` | статус неизвестен |
| `selected` | выбранная камера |
| `hover` | наведение мыши |
| `cluster` | группа камер |

### Требования

- online-камера должна визуально выделяться;
- offline-камера должна быть приглушенной;
- selected-камера должна быть явно активной;
- cluster должен показывать количество камер;
- маркеры не должны загрязнять карту.

## 5.4 Sidebar / панель карты

Sidebar должен содержать:

- поиск;
- фильтры;
- список камер;
- информацию о выбранной камере;
- результаты поиска камер по выбранной точке.

### Поиск

Поле поиска:

```text
Найти место, улицу или камеру
```

### Фильтры

Фильтры:

- статус камеры;
- категория;
- город;
- доступность;
- популярные;
- только live;
- камеры с аудио;
- камеры с PTZ, если понадобится позже.

### Категории

Примеры категорий:

- Туризм;
- Город;
- Природа;
- Дороги;
- Здания;
- События;
- Другое.

## 5.5 Карточка камеры

Карточка камеры открывается при клике на маркер.

### Содержимое карточки

Карточка должна содержать:

- название камеры;
- preview-изображение;
- статус;
- категорию;
- описание;
- расстояние до выбранной точки, если применимо;
- признаки камеры:
  - аудио;
  - PTZ;
  - ночное видение;
- кнопку “Смотреть”;
- кнопку “Подробнее”, если нужна отдельная страница.

### Основная CTA-кнопка

```text
Смотреть live
```

### Состояния карточки

| Состояние | Описание |
|---|---|
| default | обычное состояние |
| loading | загрузка данных |
| online | камера доступна |
| offline | камера недоступна |
| error | ошибка получения данных |
| no-preview | нет preview-изображения |

---

## 5.6 Modal / Overlay видеоплеера

После нажатия “Смотреть live” открывается модальное окно или fullscreen overlay.

### Должно быть в видеоплеере

- название камеры;
- live-видео область;
- loading state;
- error state;
- кнопка закрытия;
- кнопка fullscreen;
- статус live;
- возможно кнопка “Пожаловаться на камеру” позже.

### Состояния плеера

| Состояние | Описание |
|---|---|
| loading | подключение к потоку |
| playing | поток воспроизводится |
| buffering | буферизация |
| offline | камера недоступна |
| error | ошибка запуска потока |
| retry | возможность повторить подключение |

### Тексты ошибок

Примеры:

```text
Камера временно недоступна
```

```text
Не удалось подключиться к трансляции. Попробуйте ещё раз.
```

## 5.7 Клик по месту на карте

Это важный сценарий продукта.

Пользователь может кликнуть не на камеру, а на произвольное место на карте.

Система должна показать камеры, которые реально смотрят на выбранную область.

### UI-сценарий

1. Пользователь кликает по месту на карте.
2. На карте появляется маркер выбранной точки.
3. В sidebar появляется блок:

```text
Камеры, которые смотрят сюда
```

4. Система показывает список подходящих камер.
5. Если камер нет — показать empty state.

### Визуальные элементы

Нужно спроектировать:

- маркер выбранной точки;
- круг радиуса вокруг точки, например 100 метров;
- список камер, которые покрывают эту зону;
- карточки найденных камер;
- состояние “ничего не найдено”.

### Важное UX-объяснение

Пользователь должен понимать, что выбран не конкретный пиксель на карте, а область рядом с кликом.

Можно использовать текст:

```text
Мы ищем камеры, которые смотрят на область примерно в 100 метрах от выбранной точки.
```

### Empty state

Если подходящих камер нет:

```text
Пока нет камер, которые смотрят на это место
```

Дополнительный текст:

```text
Попробуйте выбрать точку рядом или уменьшить масштаб карты.
```

## 5.8 Список найденных камер по клику

Карточка камеры в списке должна содержать:

- preview;
- название;
- статус;
- расстояние до выбранной точки;
- примерную релевантность;
- кнопку “Смотреть”.

Пример:

```text
Камера на Невском
80 м до выбранного места
Online
Смотреть
```

Не нужно показывать пользователю технический `match_score` как число `0.92`.

Лучше показать человекопонятный бейдж:

```text
Лучший обзор
Хороший обзор
Рядом
```

Обязательные breakpoints:

```text

```

- desktop version;
- mobile version.

---

## 12. Состояния интерфейса

Дизайнер должен подготовить состояния:

### Loading

- загрузка карты;
- загрузка камер;
- загрузка карточки камеры;
- подключение к видео.

### Empty

- нет камер в области карты;
- нет камер, которые смотрят на выбранную точку;
- нет маршрутов;
- нет результатов поиска.

### Error

- ошибка загрузки камер;
- ошибка подключения к видео;
- камера offline;
- ошибка поиска.

### Offline camera

Нужно сделать отдельное состояние карточки камеры, если камера недоступна.

CTA “Смотреть” в этом случае должен быть disabled или заменен на сообщение.

---

## 13. UX-требования

### Карта

- Пользователь должен быстро понимать, где камеры.
- Маркеры не должны перекрывать карту слишком сильно.
- На большом количестве камер должна быть кластеризация.
- Выбранная камера должна быть очевидной.
- Пользователь должен легко закрыть карточку камеры.

### Видео

- Пользователь должен понимать, что идет подключение.
- Ошибки должны быть понятными.
- Не должно быть резкого “пустого черного экрана” без объяснения.

### Клик по точке

- Пользователь должен видеть выбранную точку.
- Пользователь должен понимать, почему ему показали конкретные камеры.
- Если камер нет, нужно показать мягкий empty state.

## 17. User Flows

Дизайнер должен описать и показать минимум 4 пользовательских сценария.

### Flow 1 — открыть карту с главной

```text
Landing Page
  ↓
CTA “Открыть карту”
  ↓
Map Page
  ↓
Пользователь видит камеры
```

### Flow 2 — открыть камеру

```text
Map Page
  ↓
Click camera marker
  ↓
Camera card
  ↓
Click “Смотреть live”
  ↓
Video modal
```

### Flow 3 — выбрать место на карте

```text
Map Page
  ↓
Click map point
  ↓
Selected point marker
  ↓
Sidebar: “Камеры, которые смотрят сюда”
  ↓
Camera list
  ↓
Video modal
```

### Flow 4 — открыть маршрут

```text
Landing / Tours Page
  ↓
Route card
  ↓
Route detail page
  ↓
Start route
  ↓
Step-by-step camera viewing
```

## 18. Ограничения

Дизайнеру не нужно проектировать:

- сложную админ-панель;
- backend-логику;
- stream protocols;
- настройки RTSP;
- управление пользователями;
- billing;
- AI-функции;
- мобильное приложение как отдельную native app.

## 19. Definition of Done

Задача считается выполненной, если:

- [ ] Есть дизайн главной страницы.
- [ ] Есть дизайн страницы карты для desktop.
- [ ] Есть дизайн страницы карты для mobile.
- [ ] Есть карточка камеры.
- [ ] Есть modal/fullscreen видеоплеер.
- [ ] Есть состояния видеоплеера: loading, playing, error, offline.
- [ ] Есть UI для клика по месту на карте.
- [ ] Есть список камер, которые смотрят на выбранную область.
- [ ] Есть empty state для отсутствия камер.
- [ ] Есть error state для ошибки загрузки камер.
- [ ] Есть дизайн маркеров камер.
- [ ] Есть дизайн кластеров камер.
- [ ] Есть фильтры карты.
- [ ] Есть страница маршрутов/экскурсий или хотя бы концепт.
- [ ] Есть базовый UI kit.
- [ ] Есть clickable prototype в Figma.
- [ ] Все компоненты названы понятно.
- [ ] Разработчик может взять макеты и начать верстку.

## 20. Главное правило дизайна

```text
Пользователь должен чувствовать, что он исследует живую карту города,
а не пользуется системой видеонаблюдения.
```

Главный пользовательский путь:

```text
Открыл сайт → понял идею → открыл карту → выбрал место или камеру → посмотрел live-видео
```
